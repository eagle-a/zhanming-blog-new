# 本地 AI 一次性投稿指南

本地 AI 可以读取文章和项目资料，也可以把一篇文章送进网站审批队列；它不能批准、公开发布、覆盖已有文章、读取数据库或写 Vercel Blob。投稿成功后的状态固定为 `pending`，管理员在 `/admin/review` 批准后文章才公开。

## 实际安全边界

不存在同时满足“全自动投稿、AI 永远看不到任何凭据、不运行独立受保护组件”的方案。当前方案选择更低的运维复杂度，用一次性投稿码限制凭据泄露后的损失：

```text
管理员在后台生成 256 位随机投稿码
→ 人把投稿码粘贴进 CLI 的隐藏输入
→ CLI 读取 AI 生成的 Markdown
→ Vercel 投稿 API 原子消费投稿码
→ Neon 待审批队列
→ 管理员预览、修改、批准或拒绝
```

投稿码有以下限制：

- 30 分钟后过期；
- 只能成功使用一次，并发请求也只有一个能成功；
- Scope 固定为 `posts:submit`；
- 只能创建一条 `pending` 投稿；
- 不能批准、发布、覆盖文章、访问后台或读取数据库；
- 数据库只保存 SHA-256 哈希，不保存明文；
- 明文只在后台生成时显示一次，刷新后无法找回。

隐藏输入避免投稿码出现在聊天、命令行参数和 PowerShell 历史中。它不是针对同一 Windows 用户下恶意进程的硬隔离；拥有当前用户完整权限的程序理论上仍可能观察进程或输入。这里依靠的是一次、短时、最小权限和人工审批，而不是虚假的“AI 绝对看不到”。

## 使用前提

首次上线需要先完成：

1. 在明确隔离的 Vercel Development/Preview 数据库执行到 `drizzle/0006_mighty_longshot.sql`；
2. 验证后再迁移 Production 数据库；
3. 部署包含投稿 API 和 `/admin/review` 的版本；
4. 配置管理员密码哈希与会话密钥。

不要在环境归属不明确的 Neon 数据库上试迁移。开发、预览和生产必须指向明确的数据库分支。

不需要安装 Windows 服务，不修改证书库、计划任务或文件 ACL。

## 文章格式

```markdown
---
title: '文章标题'
slug: article-slug
summary: '不超过 4000 字的摘要'
tags: ['标签一', '标签二']
category: 工作记录
date: 2026-08-08T12:00
---

# 文章标题

正文……
```

第一个 H1 与 `title` 相同时，CLI 会自动删除正文里重复的 H1。`slug` 只能包含字母、数字、短横线和下划线。正文可以由 AI 读取和生成，但不得包含私钥、Token、带密码的数据库地址或其他不应公开的信息。

## 每次投稿

1. 登录 `https://你的域名/admin/review`。
2. 打开“一次性投稿码”。
3. 点击“生成并复制投稿码”。
4. 在项目目录执行投稿命令。
5. CLI 出现隐藏输入提示后，由人粘贴投稿码并回车。
6. 回到审批队列预览、修改、批准或拒绝。

生产站默认使用 `https://zhanmingblog.cc.cd`：

```powershell
pnpm agent:submit C:\path\to\article.md
```

本地隔离环境显式指定 loopback 地址：

```powershell
pnpm agent:submit C:\path\to\article.md --api-url http://127.0.0.1:2025
```

CLI 只接受 HTTPS 站点 origin；仅 `localhost`、`127.0.0.1` 和 `::1` 可使用 HTTP。URL 不能含账号、密码、路径、查询参数或片段。

成功输出示例：

```json
{
  "submissionId": "...",
  "status": "pending",
  "reviewUrl": "https://你的域名/admin/review"
}
```

投稿码使用后立即失效。若网络在响应返回前中断，先检查后台是否已经出现该投稿；不要盲目重复提交。确认没有记录后再生成新的投稿码。

## 后台审批边界

后台支持 Markdown 预览、元数据编辑、批准、拒绝、生成投稿码和撤销未使用投稿码。批准动作与正式文章写入在同一数据库事务里完成；`create-only` 约束阻止 AI 投稿覆盖或复活已有 slug。

投稿 API 没有批准接口，也没有 `publish` 权限。请求正文受严格 Schema、UTF-8、2 MB 大小限制和敏感信息扫描约束。即使 AI 生成了错误或恶意 Markdown，它也只能进入待审批队列。

## 撤销与异常处理

- 未使用：在“一次性投稿码”列表点击“撤销”。
- 已使用：不能再次使用，无需人工回收。
- 已过期：自动失效；数据库保留元数据和审计记录。
- 明文丢失：无法从数据库恢复，撤销旧票据并重新生成。
- 怀疑管理员密码或会话泄露：立即轮换管理员密码哈希和 `BLOG_SESSION_SECRET`；一次性投稿码不能替代后台账号安全。

## 残余风险

- 一次性投稿码在有效期内被窃取时，攻击者可以抢先提交一篇待审批稿，但不能公开发布。
- 同一 Windows 用户下的高权限进程仍可能观察剪贴板或终端输入；彻底隔离只能重新引入独立 OS 账户、硬件密钥或受保护代理，也会重新带来运维复杂度。
- 人工审批不能省略。AI 输出可能包含事实错误、隐私、未公开研究信息或提示注入内容。
- 管理员会话仍是高权限入口，必须使用强密码、HTTPS、短会话和登录限速。
